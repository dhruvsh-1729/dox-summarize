# The whole numeric stack is held at the late-2023 generation, which is the last
# one built purely against the numpy 1.x C ABI.
#
# Why: on Railway's runtime (not on a normal VPS, where the byte-identical image
# runs fine) scipy's compiled extensions and the loaded numpy disagree at the C
# level. scipy 1.15 fails as
#   ValueError: All ufuncs must have type `numpy.ufunc`   (special/_multiufuncs)
# and scipy 1.14 fails as
#   TypeError                                             (interpolate/_fitpack_impl)
# Both are the same ABI fault wearing different hats. scipy >= 1.14 wheels are
# built against numpy 2.x headers and rely on the 2.x->1.x back-compat shim;
# scipy 1.11.4 predates that entirely and is compiled against numpy 1.x directly,
# so there is no shim to go wrong.
#
# paddleocr reaches scipy through skimage.morphology (ppocr e2e_utils imports it
# unconditionally), so these must import cleanly or PaddleOCR cannot start at all.
numpy==1.26.4
scipy==1.11.4
scikit-image==0.22.0
